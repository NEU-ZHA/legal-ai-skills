# Regulatory Reply Check Examples

## 示例一：监管问询回复前核查

### 用户意图

“这份监管问询回复今晚要发，先帮我看一下里面引用的法规和条号有没有问题，重点看结论部分。”

### 推荐处理

1. 先问：
   - 是核全文还是只核结论段、脚注和附件引用
   - 哪些结论属于高风险重点部分
   - 是否已有引用清单
2. 用 `law-recognition` 提取重点段落中的引用。
3. 用 `fatiao` 回源影响核心结论的条文。
4. 用 `citation-validator` 检查表述是否偏差。
5. 输出“与当次返回一致 / 待人工复核 / 需修正”的核查底稿。

### 不要这样做

- 不要在没锁定范围前直接扩成整篇法规研究
- 不要把“与当次返回一致”写成“回复结论正确”

## 示例二：客户回复函依据把关

### 用户意图

“客户回复函里引用了几条监管规定和行业规则，帮我先核一遍，准备给合伙人过目。”

### 推荐处理

1. 先确认：
   - 只核回复函正文，还是连附件说明一起核
   - 哪些段落会直接影响最终回复口径
   - 是否存在行业监管特殊口径
2. 优先处理重点条文，不做泛化扩写。
3. 形成可直接交给合伙人或承办律师复核的核查表。

### 最适合的交付形式

- 先给核查结果概览
- 再给逐条核查台账
- 最后单列“出具前提示”
