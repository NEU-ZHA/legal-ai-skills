# 使用示例

## 示例一：适合走综合召回

### 用户输入

```text
员工连续旷工三天，公司解除劳动合同，既想看法律依据，也想看有没有类似案例，先帮我整体找一下资料。
```

### 推荐行为

1. 这是跨法规与案例的综合问题。
2. 先拆成法规与案例两个问题，分别调用 `law-keyword` 和 `case-keyword`，预计共 50 积分。
3. 只有定向检索后仍有关键缺口时，才升级一次 `semantic-nlsql`。

### 推荐输出

```markdown
## 问题重述
当前问题同时涉及法规依据与类案样本，已先完成定向关键词检索；以下是仍需综合召回的缺口。

## 前置检查结果
- `semantic-nlsql` 已可用

## 综合召回摘要
- [此处概括本次返回的法规候选]
- [此处概括本次返回的案例候选]

## 建议的下一步分流
- 法规部分可继续交给法规检索 Skill 收窄
- 案例部分可继续交给案例检索 Skill 深挖
```

---

## 示例二：不适合走 NL-SQL

### 用户输入

```text
帮我找《劳动合同法》里关于经济补偿金的规定。
```

### 推荐行为

这类问题已经很明确是法规检索，应直接转到法规检索 Skill，而不是继续走 `semantic-nlsql`。

---

## 示例三：配置缺失时

如果未配置 `serverPaths.semantic-nlsql`，只允许输出：

```markdown
当前无法使用 `semantic-nlsql`，因为实例路径尚未完成配置。

建议动作：
- 先完成 `serverPaths.semantic-nlsql` 配置
- 验证 `pkulaw-mcp tools semantic-nlsql`
- 或改用法规语义检索与案例语义检索分别处理
```
