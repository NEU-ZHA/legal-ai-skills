# 案例卡片数据规范

输入为 JSON 数组，或对象 `{ "title": "...", "cases": [ ... ] }`。每个案例使用以下字段：

```json
{
  "classification": "实体判决",
  "title": "某甲与某乙合同纠纷二审民事判决书",
  "url": "https://example.com/source",
  "court": "某省某市中级人民法院",
  "caseNumber": "（20XX）XX民终XXXX号",
  "decisionDate": "20XX.XX.XX",
  "procedure": "民事二审；二审；判决书",
  "caseNature": "二审民事判决书",
  "keyExpressions": "与检索主题有关的关键词、合同条款、争议表述或裁判用语。",
  "issues": "与裁判判断直接相关的主体、行为、争议焦点、请求或抗辩及可核验事实。",
  "findings": "依据裁判理由压缩归纳法院的判断路径、证据边界和法律适用。",
  "disposition": "驳回上诉，维持原判。"
}
```

## 字段边界

| 字段 | 填写方法 |
|---|---|
| `classification` | 只能使用：实体判决、程序／关联裁定、重复题录、典型案例；不确定时说明具体程序性质。 |
| `title` / `url` | 标题文字本身设置为原文链接；无原文链接时不伪造 URL。 |
| `caseNumber` / `decisionDate` / `procedure` | 只填公开材料可以核验的信息；未知写“公开材料未载明”。 |
| `keyExpressions` | 摘录与检索主题、裁判判断或争点识别有关的关键词、合同条款、争议表述或裁判用语；若未出现，写“未见与本案认定相关的关键词”。旧字段 `derogatoryTerms` 仍可兼容读取。 |
| `issues` | 只写可以影响裁判判断的事实或争点，建议 150-300 字。 |
| `findings` | 从“本院认为”归纳，不要将当事人主张改写为法院结论，建议 200-400 字。 |
| `disposition` | 写裁判主文或程序结果；二审应明确维持、改判、撤销或驳回。 |

## 分类口径

- **实体判决**：公开材料可核验实体裁判结论。
- **程序／关联裁定**：管辖、保全、撤诉、终结等记录；说明程序处理，不归纳实体规则。
- **重复题录**：与另一条记录案号、日期和裁判相同；标出对应条目，不重复概括实体内容。
- **典型案例**：仅有发布摘要或发布材料；区分发布材料所载内容与未公开的原裁判全文。
